## 3. Change summary

- 修 `sync-standards.sh` 的验证目录错误：未 `cd` 进目标项目就跑 `preflight`，
  实际检查的是**当前目录所在的仓库**（通常还是 starter 自己），
  导致输出里显示的是 starter 的结果（`PASS 18`）而不是目标项目的结果。
- 验证通过时的输出措辞改清楚：区分「未引入新的 FAIL」与「其中 N 条为 worktree dirty 被忽略」。

## 4. 背景

在 recruit-site 上做首次真实同步时发现：脚本报告 `PASS 18 / WARN 0 / FAIL 0`，
但手动进项目里跑同一份 preflight 得到 `PASS 15 / WARN 2 / FAIL 1`。
两者不一致，说明验证跑在了错误的仓库上。此版本修正。
