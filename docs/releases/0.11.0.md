## 3. Change summary

- 新增 `scripts/smoke-init.sh`：**生成器冒烟测试**。
  在临时目录里跑 `init-project.sh`，然后验证三件事——
  生成物齐全、生成物能通过自己的 `preflight`、`commit-msg` 钩子既能拦不合规提交也能放过合规提交。
- CI 的 `standard` job 增加一步运行该冒烟测试。

## 4. 背景（为什么加）

此前 CI 只检查两件事：脚本语法（`bash -n`）和本仓库自身守不守规范（`preflight --ci`）。
**从未验证过「`init-project.sh` 生成出来的项目能不能用」**。

2026-11-12 实测暴露了这个缺口：用该生成器建出的仓库里，`commit-msg` 钩子要求
commit message 必须带 scope（`docs(scope): ...`），而模板与文档里没有任何提示，
直到实际提交被拦才被发现。这类回归只能靠人在建项目时撞见，属于典型的"工具自身无人验收"。

## 8. Risks and open issues

- 冒烟测试依赖 `mktemp`、`git`、`bash`；Windows 需在 WSL/Git Bash 下跑，未验证。
- CI 跑在 ubuntu 上，`init-project.sh` 的 Git 行为（默认分支名、钩子路径）与 macOS 可能不同，
  **首次远端 CI 结果才是真验证**。
- 冒烟测试用一个 `--allow-empty` 提交验证钩子，会在临时仓库里留下这两次提交（目录结束后删除）。
