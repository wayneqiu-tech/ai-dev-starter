## 3. Change summary

Patch release focused on the two hard flaws found in the 0.9.0 review:

- **Fail-closed config.** `preflight.sh` no longer falls back to a preset when
  `standard.conf` is missing, and it fails if `PROJECT_NAME` is still
  `my-project`. `--allow-defaults` is explicit and demo-only.
- **Traceability.** `preflight.sh` now checks unpushed commits, ledger drift,
  tag naming, commit message, and commit size. The baseline commit skips the
  commit-size warning.
- **Release sync.** New `scripts/check-release-sync.sh` checks
  `HEAD == origin/<branch>`, ledger / `VERSION` == live `/version`, and
  `HEAD` is tagged with a tag that matches the ledger.
- **Environment dimension.** Release guide §4.2.1 covers dev / CI / prod
  isolation, including the one-machine case.
- **DSH Skill.** `init-project.sh` installs
  `.dsh/skills/ai-dev-standard/SKILL.md`; use `/ai-dev-standard`.
- **Intro rewrite.** README now leads with the beginner outcome, not the term
  "engineering baseline".

## 7. Risks and open issues

- Still a **public beta**, not a formal standard and not a certification.
- `check-release-sync` needs `LIVE_VERSION_URL`; without it, the live check is a WARN.
- Environment isolation is documented, not enforced by a check.
- `init-project.sh` still targets new projects; there is no `--existing` mode yet.
- CI is still the project's responsibility; the standard does not replace it.
- `preflight` tag/commit checks are heuristics; they can warn on legacy history.
