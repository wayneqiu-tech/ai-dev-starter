## 3. Change summary

- 新增 `scripts/sync-standards.sh`：把新版规范同步进**已装规范的项目**。
  默认只预览差异，`--apply` 才写入；写入前备份，写入后跑 `preflight` 验证。
  只同步 `<项目>/docs/standards/**`，绝不碰 `standard.conf`、`AGENTS.md`、`README.md`、
  `STATUS.md`、`docs/releases/**` 这些项目自己的东西。
- `init-project.sh`：不再把 starter 专属工具（`smoke-init.sh`、`sync-standards.sh`）
  复制进下游项目。
- `smoke-init.sh` 增加断言：生成物中不得出现上述两个脚本。

## 4. 背景

`init-project.sh` 是**复制**规范进项目的，不是引用。因此 starter 升级后，
已装项目不会自动更新，只能手动复制——而手动复制迟早导致"不同项目跑不同版本的规范"。
本版本提供唯一一条明确的升级通道，并把"哪些文件归标准、哪些归项目"写死在脚本里。

## 8. Risks and open issues

- 同步是**覆盖式**（`rsync --delete`）：如果项目在 `docs/standards/` 里加了自定义文件，
  会被删掉。这是有意设计（该目录归标准所有），但必须在文档里讲明。
- `worktree is dirty` 属于同步的必然结果，脚本忽略该条 FAIL；其它 FAIL 仍会回滚。
- 尚未处理"项目版本 < 0.11.0 且脚本路径不同"的迁移场景。
