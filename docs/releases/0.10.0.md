## 3. Change summary

- **Two lanes**: Fast and Controlled. Fast may batch 3–5 small changes in one
  PR; Controlled needs its own PR, tests, rollback note, and staged release.
- **One feature per branch**: a feature can hold 5–8 commits; stop creating a
  branch per interaction.
- **Gate protocol**: Plan / Merge / Release / **Next**. One gate approves one
  action; no "always allow" for merge, deploy, or delete.
- **`GATE: next`**: every finished task ends with one executable next action
  plus `stop`; no "if you want, I can..." prose.
- **`STATUS.md`**: one capability table (status / evidence / gap); README only
  links here.
- **`verify.sh`**: fixed summary
  (`VERIFY typecheck=... test=... build=... a11y=...`); `init-project.sh`
  installs it as `scripts/verify.sh`.
- **PR templates**: lane, verify summary, gate approval, STATUS update.
- **`init-project.sh`** now installs `STATUS.md` and `scripts/verify.sh`.

## 7. Risks and open issues

- This changes the recommended workflow; readers of 0.9.3 docs may still create
  a branch per interaction until they re-read `AGENTS.md`.
- No DSH button plugin yet: clickable gates use the host's question/approval UI;
  otherwise they are numbered options.
- Semantic checks (stale README claims, route titles/axe, migration required,
  API test waiver) are intentionally **not** hard-coded; they belong in
  project-specific `checks/*.sh` hooks.
- Still a public beta, not a formal standard or certification.
